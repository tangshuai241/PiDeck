# TPA 个人工作台功能区与迁移方案

日期：2026-10-14。版本：1。

状态：客户端与接口代码已完成开发和隔离验收，进入代码提交。用户已确认待办共用一份，云端为正式来源，TPA 保存缓存与待确认修改。P03、P04 的功能验收已完成；P02 的正式 HTTPS 接入与迁移、P05 的正式服务部署和日常安装版交付仍未完成。2026-10-15 用户要求暂缓 UI 优化工作树的合并。本方案只安排必要测试，不安排 loop 命令。

## 1. 目标与已确定的范围

用户日常只打开自己的 TPA。左侧有固定的个人功能入口，中间可以查看待办和阅读材料。聊天、项目开发与后台运行继续沿用现有能力。

首批接入阅读、待办。后续功能接入同一区域。界面沿用当前主题、字体、缩放和布局设置。

```text
个人工作台
  阅读
  待办

会话
  活动 · 聊天 · 项目
  原有会话列表

底部
  设置
```

实施顺序为数据核对、导航、待办、阅读、对话关联、日常交付。菜单中的展示顺序仍为阅读、待办。

本轮不重做任务执行器、不全量移植旧工作台、不新增书源、不重写 EPUB 解析器。自动分类、自动规划、主动提醒和云端整书存储作为后续增量。已有历史记录及关联信息应保留。

## 2. 完成后的使用场景

### 2.1 待办

用户点击左侧“待办”，查看分类、日期、背景和子待办。用户可以新增、修改、勾选完成和重新打开事项。保存失败时，页面保留输入并说明状态。

用户可以从待办查看来源对话。需要助理协助时，用户把选中的事项带回聊天。系统保留待办身份及本次背景快照，当前 Pi 会话继续处理。生成回答或成果不自动勾选待办。

### 2.2 阅读

用户点击“阅读”，打开已有书库，按作品与版本选择书籍。页面显示目录、正文、阅读位置、笔记和关联会话。用户重开应用后可以继续阅读。

用户选中书段并交给助理时，系统只带入本次书段、书籍版本和原文位置。用户可返回该书的关联 Pi 会话；切换书籍不会把上一书的迟到回答写到当前书。

### 2.3 页面切换

用户从聊天切到待办或阅读时，当前运行时继续工作。切回聊天时，系统保留会话、草稿和滚动位置。功能页不通过切换入口停止或重启 Pi。

页面读取与手工保存不调用模型。首版不新增工作台模型工具；用户发送选中的材料后，Pi 才调用模型，不把全书或全部待办放入每轮上下文。已发送材料仍属于正常 Pi 会话历史，后续模型请求是否包含它由 Pi 的上下文管理决定，不能承诺后续没有这部分 token 消耗。

## 3. 当前核实的事实与待确定项

以下包含源码检查和 2026-10-14 的只读数据核对，不代表本轮已完成迁移或界面验收。

| --- | --- | --- |
| 左侧导航 | TPA 已有活动、聊天、项目与独立侧栏控制器 | 增加个人功能区，保留原有会话选择行为 |
| 工作区页面 | TPA 已有工作区内容与宿主插件 page 呈现能力 | 复用工作区挂载方式；页面切换与会话身份分别管理 |
| 本地待办 | Workbench 按事项保存 JSON，已有分类、日期、背景、子待办和关联任务规则 | 提取数据规则及界面行为，不搬入整套工作台运行时 |
| 云端待办 | 已有列表、创建、状态和任务关联接口 | 尚不能直接替代本地待办；正文编辑、日期、子待办和并发版本保护需要补齐 |
| 阅读 | DeepRead 有稳定作品／版本身份、书库与按书关联历史的实现 | 直接核对并接入既有阅读服务，保留不同版本与历史归属 |
| 既有阅读教练 | DeepRead 当前聊天入口有自己的模型流程 | TPA 新阅读对话走 Pi；旧阅读对话按原来源读取，不改写成 Pi 原生消息 |
| 日常数据 | 当前用户已采用单个日常安装入口，开发期数据已补接 | 后续更新使用同一日常目录；发布前核对启动位置与数据目录 |

### 本次只读核对结果

本地有 44 条待办，云端有 58 条。本地 44 条在云端均有相同身份，核对标题、状态、分类、日期、背景、关联和子待办数量未发现差异。接入时沿用这些身份，不重复创建。云端额外记录包含已展开的旧子待办及历史记录，应先识别来源，不按总数差异删除数据。

部分旧任务关联无法在云端找到完整来源。首版保留关联并显示来源暂不可用，不重新执行任务，也不凭推断补写来源。旧工作台现有冻结接口尚不能证明所有后台写入已经停止；正式切换前必须补齐冻结覆盖或完成受控停写和队列排空。

DeepRead 当前服务可连接，书库、目录和按章正文接口可复用。现有服务缺少阅读位置保存 API 和手工笔记写入 API，旧笔记也未全部具备精确段落定位。新接口必须保留原笔记来源；无法定位的旧记录显示未定位，不生成猜测位置。旧阅读会话目录需要单独读取，不能仅以当前会话列表的数量判断历史是否完整。

DeepRead 的部分 GET 接口会扫描并写入索引，不能作为无副作用读取。原文定位还需校验书籍内容版本，避免旧缓存返回另一版本的位置。当前服务免鉴权是环境事实；未来启用鉴权后，接入应保留正常认证及受保护凭据。

### 待办的数据来源选择

用户已明确选择电脑与云端／微信共用同一份待办：云端保存正式记录，TPA 保存读取缓存及待确认写入。账号、事项身份和数据来源统一，正式写入走云端确认。

采用云端方案时，TPA 复用当前已连接的云端账号与受保护凭据，连接信息在现有设置页显示。用户不必新增一套账号或重新查找密码。

本轮按云端正式来源实施。离线缓存和待传队列按账号隔离，待传内容不能被显示为已获得云端确认。

阅读首版复用现有书库与笔记来源。TPA 保存书籍身份、阅读位置和会话关联。书籍文件不默认复制到云端记忆服务。

## 5. 架构与职责

首版使用 TPA 原生 React 页面。参考旧工作台的业务规则与交互，采用 TPA 的 Jotai、Tailwind、shadcn、i18n 和语义 token。无需为首版增加新插件框架或第二套状态管理。

| 位置，均为拟新增或薄装配 | 职责 |
| --- | --- |
| `src/shared/types/personalWorkbench.ts` | 页面身份、功能状态与导航契约 |
| `src/shared/types/personalTodo.ts`、`src/shared/types/reading.ts` | 待办、书籍、位置、笔记和关联身份 |
| `src/renderer/src/atoms/personal-workbench-atoms.ts` | 当前功能页、折叠状态与页面恢复信息 |
| `src/renderer/src/hooks/usePersonalWorkbench.ts` | 统一导航、返回会话与页面生命周期 |
| `src/renderer/src/components/personal-workbench/` | 左侧功能区与页面容器 |
| `src/renderer/src/components/todos/`、`src/renderer/src/components/reading/` | 各自领域的视图与交互 |
| `src/main/personal-workbench/` | 待办适配、阅读适配、缓存、笔记与迁移记录；按职责分文件 |
| `src/main/ipc/personalWorkbenchIpc.ts` | 入参校验与领域调用；通道在 `src/shared/ipc.ts` 登记 |
| Pi 扩展，按功能需要注册 | 读取选中材料、事项记录及会话关联；只用现有 stdio RPC |

`App.tsx` 和 `main/index.ts` 只增加装配。单文件目标不超过 400 行。原会话选择与新功能页选择分别保存；页面切换不伪造 sessionId，也不清空当前运行时身份。

渲染层只调用 preload。主进程访问已登记的云端接口和阅读服务。服务地址、认证与书库路径在主进程校验，凭据不进入渲染层或日志。

TPA 可复用 DeepRead 的书库、正文和笔记接口。TPA 新阅读问答不转发到旧工作台或 DeepRead 的聊天模型入口，模型调用继续由 Pi 负责。适配器只管数据，不承担第二个 Agent 的职责。

页面按需读取数据。未打开阅读页时，不初始化阅读服务连接、不扫描全书库。隐藏页面暂停轮询，保留草稿与位置；关闭页面时清理订阅和定时器。应用只停止本次自己启动的服务进程。

## 6. 数据迁移与保存规则

### 6.1 先核对，再导入

P00 只读核对以下资料，输出数量、来源、重复项、缺失项和能力差异。

- Workbench 待办、分类配置、子待办、旧任务与来源关联。
- 云端当前账号的待办和关联任务。
- DeepRead 的书库配置、作品、版本、阅读记录、笔记与旧会话。
- TPA 当前会话、关联身份和已保存的云端账号。

实施负责人核对实际运行数据根；不根据旧 README 的端口、目录或条目数量直接迁移。账号及身份冲突列出具体来源，不按标题合并。

正式迁移前独立备份来源与目的地。记录文件哈希、记录数和备份位置。不可变书籍原件保留原位置；新页面通过已验证的书籍身份与受限路径读取。

### 6.2 保留身份和出处

- 待办、子待办和分类保留原编号。云端已有相同编号但内容不同的记录时，迁移建立明确映射，保留两个来源，等待确认。
- 保留标题、背景、备注、日期、创建时间、修改时间、完成状态与旧任务关联。日期保留原值及解析结果，不把未知时间猜成午夜。
- 作品按 `work_id`，版本按 `edition_id` 关联。笔记和阅读位置应关联到具体版本与正文位置，不按书名或百分比猜测。
- 旧会话保留原格式。不同会话来源的原生编号不能互相替代；新旧身份的映射单独保存。
- 导入记录带来源编号和内容哈希。重复运行迁移不重复创建，不触发模型，不执行旧任务，也不自动勾选事项。

### 6.3 正式写入与离线行为

P00b 已固定以下映射。执行记录与只含身份的映射副本保存在本轮验收目录，正式切换时重新核对当前资料。

| 来源资料 | 目的地与规则 |
| --- | --- |
| 已存在云端的 44 条本地待办 | 沿用云端同一身份；字段一致时不写入，不重复创建 |
| 4 个父项下的 12 条旧子待办 | 沿用云端全局身份，以来源命名空间、父身份和原子项身份回查；页面嵌套在父项下 |
| 云端额外历史与新增事项 | 保留身份及来源；不按数量差异或标题清理 |
| 旧任务关系与悬挂关联 | 保留原关联；未核验和无法找到分别显示，不重放执行 |
| 书籍作品、版本及正文 | 正式来源仍为 DeepRead；TPA 按作品、版本和内容版本读取，不全书上传记忆服务 |
| 阅读位置及手工笔记 | 新位置绑定具体版本；笔记写回既定笔记来源。旧笔记无法定位时保留原文及来源，标记未定位 |
| 两个来源目录的旧阅读会话 | 按各自来源身份读取，保留原消息格式；不以当前目录列表代替完整历史，不伪装为 Pi 会话 |

这一映射是设计完成记录。它不证明正式数据已经切换，也不证明旧后台写入已经停止。

采用云端正式记录时，写入携带稳定 `request_id` 和预期 revision。账号来自已认证身份。服务端持久化成功后返回确认；TPA 收到确认后才显示已保存。

断网时可查看最近缓存、保留编辑草稿。提交的变更进入持久化待传队列，显示“待云端确认”。重启后恢复队列并查询原请求结果，再决定重试。版本冲突保留用户输入并展示差异，不静默覆盖云端新内容。

首版本地缓存不充当另一份正式主账。用户更换账号时，缓存、草稿与队列按账号隔离，旧账号待传不发送到新账号。

阅读位置与笔记保存也区分“输入仍在”“已保存”“保存失败”。笔记写入既定笔记来源，TPA 只缓存投影。更换书籍或版本后，迟到响应仍归属原对象。

### 6.4 迁移切换与回退

先用临时副本验证迁移，再对明确选定的正式数据导入。首次读取完成后核对记录数和字段，才切换新入口。

切换后，旧工作台对已迁移待办停止写入，旧记录保留只读备份。若旧程序尚不能限制写入，先停止该待办写入口，再切换；不同时允许两端分别维护不同的正式记录。

回退界面或代码时不恢复旧备份覆盖新写入。回退前检查待传队列，并保留迁移后的新增内容。旧执行档案继续按原来源读取，不重新分发。

## 7. 对话与个人功能的关联

用户明确说“记一条待办”或在页面提交时，即授权保存该条事项。助理提出的行动选项不自动登记为待办。事项变更引用当前对象编号与版本，存在歧义时先定位对象。

待办带回聊天时，绑定 `todo_id`、可选 `subtodo_id`、来源与背景版本。旧任务及成果只读；首版新文稿沿用 TPA 当前文稿流程。页面显示原始记录、程序检查与用户完成确认各自的状态。

阅读问答绑定 `work_id + edition_id + sessionId`。默认保留每本书的独立会话；用户可另建同一本书的会话。书籍切换不改写已有 Pi 会话所属对象。

材料选择在发送时固定为本轮快照。工具只返回本次需要的段落或事项，带来源和分页标识。运行时命令与迟到结果仍检查 `sessionId + agentId + runtimeGeneration`。

可长期保存的偏好和经验继续走现有记忆流程。书籍正文、笔记库与待办主账各有正式来源，Hindsight 不取代这些来源。

| P03 | DeepRead 数据适配、书库、目录、正文、位置、笔记与旧阅读历史 | 一个作品的不同版本共存；重新打开回到具体版本的位置；笔记保存后可回读；服务中断说明原因并保留草稿 |
| P04 | 事项及书段进入 Pi；每书会话关联；一次性材料与来源定位 | 对话归属稳定；切页或切书后迟到结果不串对象；选中的原文及事项来源可回看；普通会话不每轮读取工作台数据 |
| P05 | 正式导入、固定版本打包、同一个日常入口更新、回退与记录 | 实际安装版显示迁移资料；原件和备份可核对；旧写入口收口；云端账号、人格、Engram、聊天与项目能力保留 |

开发按顺序收口。P01 到 P04 可使用临时数据展示未完成页面，但日常交付不以可点击的空页面冒充功能完成。

### P04 的实现边界

首版材料入口只把用户选中的书段或待办追加到明确目标 Pi 会话的输入框。按钮不发送消息、不调用模型。用户发送后，来源身份与原文作为该次消息的快照保留；下一次普通提问不再次附加工作台材料。绑定按作品与版本持久化，失效绑定须明确处理，不静默新建替代会话。复用既有引用与 stdio RPC 发送链路，不增加 GUI 通用桥或每轮工作台读取工具。

真实 Pi 问答已完成一次实际用户发送：指定 Magpie 路由 `group/auto-deepseek-v4-1-flash`、思考级别 `max`。Pi 原生 JSONL 中有一个用户消息、一个正常结束的助手消息，材料块和实际选中的原文均只出现一次，没有工具结果。界面最终回答与原生记录一致。输入 695、输出 71、共 766 个 token；首段助手正文可见约 2.8 秒，完整回答约 3.0 秒，包含运行时激活时间。自有进程退出，跑前跑后源码与构建一致。

模型请求快照断言未通过：本次未打包验收启动没有加载快照扩展，生成的请求快照为零。原失败日志保留，功能补充核对依据是 Pi 原生日志、实际可见回答和进程归属证据，不把它说成快照验收通过，也不声称已独立测得供应商底层请求次数。SDK 费用只是本地估算，供应商实际账单未知。未为修正采样额外调用模型。正式发布时另核对随包资源与快照功能。

## 9. 必要测试与验证范围

测试只覆盖本次新增行为和本次改动影响的边界。已有 EPUB 解析、书源、模型供应商、云端记忆与旧工作台任务链路不整套重测。

| 改动 | 必要自动检查 | 必要实际检查 |
| --- | --- | --- |
| 导航与页面容器 | typecheck；导航状态、返回会话、迟到结果归属的行为测试 | 一次真实 Electron 切换阅读／待办／聊天；核对草稿、位置、当前主题与运行状态 |
| 待办与存储 | 创建／更新、父子完成规则、版本冲突、重复请求、原子写失败、迁移重复执行 | 临时验收事项经历新增、编辑、子待办和重开；不修改原有真实事项作为测试 |
| 云端待办适配 | 涉及接口的账号隔离、请求确认、断网后恢复与并发冲突 | 同一账号的正式 HTTPS 读取及一条明确标记的验收事项；原请求只恢复，不重放未知操作 |
| 阅读适配 | 作品／版本匹配、位置恢复、笔记保存失败、切书迟到响应、输入路径校验 | 两个小型隔离 EPUB 版本；保存一条合成笔记并重开；正式书库只读核对 |
| Pi 会话关联 | 绑定身份、材料快照、工具参数、迟到响应与来源标识 | 只在新问答链路离线检查通过后，用一个短书段做一次真实 Pi 回答；必要时同轮核对事项，不安排多组盲评 |
| 发布与正式迁移 | typecheck、针对性测试、格式与构建；迁移字段及哈希核对 | 真正使用的安装目录、数据目录、账号和功能页；切回普通聊天与项目各检查一次 |

本轮按用户明确要求仅运行必要检查：类型检查、相关行为测试、构建与固定候选的真实界面验收，不重复运行全量套件。候选改变行为时补跑受影响测试；已通过的批次不相加，也不把采样失败改成通过。

布局、颜色、图标和简单展示字段不新增源码字符串扫描测试。新增主进程业务、数据转换、状态机或 bug 修复应有行为测试。重复提交、冲突、失败留稿和数据归属不能以截图替代。

默认自动检查使用临时目录、假服务和假模型，真实模型调用为 0，微信发送为 0。真实问答单独记录模型请求数、用量、耗时和保存状态；供应商账单未提供时写未知，不将 SDK 估算当成实付费用。

测试预算按覆盖风险控制，不先定测试条数。通过关键检查且没有新疑点时进入下一节点；不安排连续压测或反复人工验收。

## 10. 速度、用量与推进方式

界面先显示结构，再读取当前页数据。待办读取第一页，书库读取目录及当前章节；页面加载不等待模型整理。写入回执、后台上传和模型回答分别显示，不能把它们合成一个耗时数字。

记录页面首次可用、接口返回、保存确认、模型首字、完整回答和失败情况。初期只记录，不设置新的速度门槛，不增加每轮强制检索。

加快推进的措施：

1. 复用现有数据规则、阅读解析和认证，首版页面采用现有 UI 原语。
2. P00b 只读核对后固定接口，不边写界面边猜数据格式。
3. 先接通待办主路径，再接阅读主路径，自动化能力留到后续。
4. 每节点只跑涉及的检查，真实模型验收集中一次。
5. 复用同一个日常安装目录；临时验证环境保留明确标识，验证数据不混入正式资料。

P00b 完成后再根据实际接口缺口估算时间。目前已确认云端待办缺少本地完整编辑能力，不能承诺只增加两个按钮即可完成迁移。实施负责人按节点报告已经可用的场景和剩余工作，不把至少三个使用日的观察算成开发等待时间。
