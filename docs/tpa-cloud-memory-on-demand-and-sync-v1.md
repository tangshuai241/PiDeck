# 按需读取云端记忆与本地对话回传

日期：2026-10-14。
状态：按需读取、人格缓存、原话采集、持久队列、后台回传及整理已开发，独立环境的真实 Pi／Hindsight 与两端回读已验收。用户已授权源码提交；功能默认关闭，未发布、未在正式服务启用。范围与限制见[工程验收记录](tpa-cloud-memory-acceptance-v1.md)。

本文保留设计概要。详细节点、依赖、交付物和验收标准以[实施方案](tpa-cloud-memory-implementation-plan-v1.md)为准，节点勾选只在该方案维护。

## 已确定的方向

Pi 当前模型需要历史资料时，调用云端记忆工具。不在每个用户回合自动检索。工具结果通过 Pi 原生会话上下文供模型读取，TPA 仍通过 stdio JSON-RPC 管理 Pi。

记忆读取和对话回传分别运行。读取决定本次回答要看什么；回传负责把本地原话保存到云端。回传不触发云端再次回答，也不要求回答等待上传完成。

## 读取的条数与大小

不采用固定三条截断。搜索以正文文本预算控制返回量，条数随记录长度变化。正文默认 500 token，可请求 1 到 4096；安全条数上限为 50。该默认值不是经测试确定的最佳值。

搜索结果先给候选预览、稳定记录编号、来源、时间和作用范围。预览标明是否完整，不把片段当成完整原话。来源和包装也占模型输入用量，因此正文预算不等于最终工具结果的严格 token 上限。

需要完整依据时，模型指定记录读取原文。长记录分段读取，并返回总大小、片段位置和继续读取位置。原始存储保持完整。没有查询工具的回合，不额外加入记忆正文。

同一会话中已有的记忆工具结果遵循 Pi 正常上下文与压缩行为，模型可直接使用，不另复制一份隐藏注入。需要其他历史时再查。工具结果会随原生会话记录保存，这与旧实验版仅存在于本轮内存的 hidden custom 消息不同。

## 本地原话如何回传

已实现以下链路：

1. Pi 的原生会话继续保存用户输入与助手回答。
2. 回传模块把新增可见对话登记到本地持久待传队列。
3. 后台按账号、设备、会话和来源消息编号上传新增记录。
4. 云端通过专用的原话导入入口落盘，并返回编号和内容哈希回执。
5. 本地核对回执后标记已同步。

断网或认证失效时，待传记录留在本地，恢复条件后继续上传。程序重启也不丢待传状态。重复提交同一来源记录和同一内容不创建重复消息；同一编号出现不同内容时报告冲突。编辑和删除表达为新修订或可见性事件，原始版本保留。

每条记录至少保留账号归属、设备来源、Pi 会话身份、来源消息编号、角色、发生时间、原始可见文本、项目标签和父消息关系。用户原话与助手回答分别存储，助手推断不改写为用户陈述。

## 回传范围

用户已确定：个人与项目会话都归档用户输入和助手可见回答，并保留项目标签。首版从启用后的新增消息开始；历史会话未选定，因此不自动回补。

工具输出、思考过程、系统提示和自动读取的文件正文不随可见对话原话导入。附件先保存引用和归属；实际文件上传另走文件能力。用户直接粘贴在消息里的材料仍是该消息的一部分。

## 原话归档如何成为长期记忆

云端先保存原始对话，再由后台整理识别值得长期保留的信息。整理出的条目关联原话编号、时间和账号／项目归属，写入 Hindsight 后仍能回查原话。

明确的用户事实、偏好与决定，和待确认推断分别标记。问过某个方案不代表已作决定；助手提出的方案不代表用户接受。更正时保留旧来源并表达失效或替代关系。

归档每条对话不等于把每条对话都写为长期记忆。后台整理不位于本地回答前置路径；使用整理模型时单独记录耗时和用量。

## 已核实的云端接口边界

现有 `POST /api/cloud/conversations/:id/messages` 会调用 `assistant.enqueue`，随后触发 `processConversation`。不能用它上传已在本地回答过的聊天，否则可能再次生成云端回答。

现有 `import-personal.js` 支持把历史标为 `imported/completed`、不进入执行队列，但它是隔离目录的离线导入工具，不能直接用于在线回传。

`message-archive.js` 提供原有云端消息归档。新增 `desktop-memory` 领域独立接收桌面原话，保留来源与修订，通过专用 API 导入及分页读取；桌面不直接写云端文件。

按编号读取记忆的接口已接入来源门面。`search_memory` 返回摘要与来源引用，`get_memory_source` 按来源／记忆编号读取原话，续读必须绑定原文哈希。云端助理另外具有只读档案搜索与读取工具，可查尚未成为长期记忆的原话；首版没有独立的档案浏览页面。

## 实现顺序

1. 将实验版改为 Pi 原生只读搜索与详情工具，移除每轮自动检索及三条截断。
2. 保留检索、工具调用、模型请求和输入用量的分阶段记录。
3. 新增云端在线原话导入领域入口，保证仅保存、不生成回答。
4. 实现本地持久待传队列和后台同步。
5. 衔接云端原话检索与后台记忆整理，保留来源关系。

正式启用仍需处理旧记忆的账号归属、有效用户认证、版本发布和日常桌面验收。当前正式库的旧资料没有自动补标签。

## 验证范围

读取验证覆盖按需触发、无调用时零召回、完整候选不被三条截断、详情来源核验、分段完整性、取消和错误行为。

回传验证覆盖重复提交、断网恢复、进程重启、内容冲突、消息编辑、账号隔离和原文一致性。云端导入的模型请求数应为零；后台整理的模型请求另计。普通回答不以云端上传完成为前提。

真实验收需要证明：电脑端形成的新原话能够在云端回读；随后云端入口和电脑端工具都能按来源找到同一条资料。源码与隔离测试不能代替该验收。
