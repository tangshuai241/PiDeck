## 用户会得到的行为

普通编程、计算和文件工作使用当前材料。Pi 不在每轮强制检索云端；有需要时调用 `search_memory`，再用 `get_memory_source` 核对原话。已经进入会话的工具结果仍遵循 Pi 的上下文与压缩规则，后续模型请求仍可能为这些内容计费。

个人与项目可见对话均可后台归档，保留实际项目标签。上传只存原话，不让云端重新回答。确认回执前保留本地待传记录。云端后台整理使用有来源的资料；问题、未决事项和助手推断不会直接成为已确认个人事实。

人格使用云端已确认版本及本地缓存，后台检查更新。相同资料和人格来源不保证两端逐字回答一致。Engram 保留，云端工具负责个人／项目历史，既有工程经验仍可使用 Engram。

## 耗时与用量口径

原生历史回合首个可见文字为 14.157 秒，普通 JSON 回合为 3.188 秒；云端查询完整回合为 16.23 秒。题目与工具路径不同，且验收含 SSH 中继，不能据此计算生产额外延迟或稳定速度。未设置速度门槛。

原生两轮共 3 次供应商请求，记录输入 3022、输出 1261、缓存读取 4608 token。桌面个人回读另有 3 次请求，逐请求 usage 已保存；云端回读记录 3 个模型回合。调用数与 token 不能相互替代，SDK 费用估算不是账单。

后台首次有 2 次空正文失败，其实际 usage 未被旧实现保存，记为未知。修复后提取复用配置输出预算，失败用量可保留。Hindsight retain 内部模型次数和账单未由该接口提供，不计为零，也不以一次 HTTP 请求冒充一次内部模型调用。

## 失败与恢复

1. 后台提取原来硬编码 1200 输出 token，推理模型两次空正文。先做复现，再改为使用配置预算；失败不推进来源游标、不损坏原话，并保留合法失败 usage。最后涉及该改动的模型客户端及提取测试共 26 项通过。
2. 临时 SSH 中继的 Windows 字符编码导致中文 retain 在发往远端 HTTP 前失败。中继改为严格 UTF-8；核对原来源与缓存候选后，用同一稳定文档编号受控恢复，没有重发用户回合，也没有再生成提取候选。真实单位和来源随后核验成功。
3. GUI 脚本没有选择预置的测试项目，实际进入个人会话；还读错嵌套状态、依赖不存在的 idle 字段、将原话 JSON 字符串直接传给对象解析器，并只按 source_id 定位 memory_id 工具结果。原失败报告完整保留。主负责人根据原生记录、真实 HTTP 和只读运行状态另作 20 项核验，没有额外发送问题。该次只认定为个人会话验收；项目会话由原生 Pi 案例证明。
4. GUI 此次禁用断言没有等待异步开关状态，不作为成功证据；设置禁用证据来自独立 N04 真实操作。不会把两次记录合并成一次全部通过的 GUI 脚本。
