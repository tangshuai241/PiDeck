# 早期自动召回实验记录（历史证据）

日期：2026-10-13。
状态：历史实验归档，不描述当前实现。当前代码已采用按需工具；正式云端版本未发布，日常 TPA 未启用。

本文记录开始实施前的自动召回实验，以下“第一版”、三条限制及隐藏注入均指当时的实验。当前按需工具、后台归档和真实两端验收见[实施方案](tpa-cloud-memory-implementation-plan-v1.md)及[工程验收记录](tpa-cloud-memory-acceptance-v1.md)，不得据本文恢复每轮召回。

## 目标

Pi 读取云端个人记忆，并记录每个阶段的耗时。用户要求先记录，再根据记录决定性能策略。

新接入路径没有性能期限。请求慢时，Pi 等待返回。用户主动取消、会话切换或进程关闭时，扩展取消请求。

第一版没有自动重试、跨回合缓存、反思模型或记忆写入。原云端助理的既有召回路径保持其原配置。

## 入口与职责

TPA 把 `pi-deck-cloud-memory.ts` 登记为默认关闭的内置扩展。用户启用后，Pi 通过公开扩展事件读取资料。TPA 和 Pi 仍通过 stdio JSON-RPC 通信。

扩展在 `before_agent_start` 建立回合记录。在首次 `context` 事件中，扩展发起一次召回。这个阶段已有 Pi 的取消信号。同一回合的工具循环复用召回结果；新用户回合重新查询。

云端提供 `POST /api/cloud/memories/recall`。接口使用现有用户会话 Bearer 认证和 `memory` 权限。设备凭据不能访问这个接口。服务器决定账号和 bank，调用方不能指定其他账号或 bank。

## 配置

默认配置位于 Pi 用户目录的 `pi-deck-cloud-memory.json`。设置了 `PI_CODING_AGENT_DIR` 时，扩展使用该目录；否则使用 `~/.pi/agent`。

配置字段如下。

| 字段 | 含义 |
|---|---|
| `enabled` | `true` 才读取记忆 |
| `mode` | `personal` 允许个人召回；`project` 不查询个人历史 |
| `baseUrl` | 云端助理地址；只接受 HTTPS 或回环 HTTP |
| `authFile` | 保存用户会话 `token` 的本地 JSON 文件绝对路径 |
| `logFile` | 观察日志的绝对路径 |

认证文件不保存密码或 Hindsight 主令牌。扩展不自动登录或刷新会话。会话失效时，扩展记录 HTTP 错误。

配置、认证和日志路径应位于 Pi 目录或明确的应用数据目录。查询、正文、思考内容和认证字段不进入观察日志。

第一版用连接文件配置，不提供新的登录面板。日常启用前，应准备有效用户会话，并发布云端接口。不能仅打开扩展开关就声称已连接。

## 召回与注入

查询只包含当前用户消息和最多三条最近的用户文本。查询不包含系统提示、工具结果、图片内容或自动读取的文件正文。

扩展使用原生 recall，不调用 reflect。默认请求最多三条记录和 500 token 文本预算。这些限制控制载荷大小，不是耗时门槛。

服务器使用 `user:<账号>` 和 `all_strict` 过滤，并在返回边界再次检查归属和有效状态。未标记归属的旧资料不会自动视为当前账号所有。

Pi 把返回资料作为隐藏的 custom 消息加入本轮内存上下文。扩展保留来源，不用第二次聊天模型改写资料。扩展不把这段记忆正文追加到会话文件。

用户明确要求“不用历史”或“只按本轮材料”时，扩展不查询，并记录原因。“只输出 JSON”本身不触发跳过。

## 记录字段

| 字段 | 起点与终点 |
|---|---|
| `recall_ms` | 本地发起召回至读取并校验响应完成 |
| `prompt_to_request_ms` | Pi 建立回合记录至首个模型请求 |
| `request_to_first_event_ms` | 首个模型请求至首个非空思考或文字增量 |
| `request_to_first_text_ms` | 首个模型请求至首个非空文字增量 |
| `turn_ms` | Pi 建立记录至回合结算 |
| `server_timing.hindsight_ms` | 云端接口等待下游 Hindsight 调用的时长 |
| `server_timing.server_total_ms` | 云端接口认证、读取和返回处理的总时长 |

日志还记录回合 id、会话 id、状态、跳过原因、模型请求数、注入字符数、来源 id 和模型返回的 usage。

扩展使用 `performance.now()` 计算时长。ISO 时间只用于定位记录。缺失的首字或服务端字段为 `null`，不能记为 0。服务器和扩展通过回合 id 关联，不用两台机器的时钟差推算网络耗时。

这里的“首字”是 Pi 收到首个文字增量，不是 Electron 完成绘制的时间。扩展起点也不包含窗口操作和冷启动。真实桌面体感需要继续记录这些阶段。

日志到 1 MiB 后轮换，保留一个备份。Pi 还把不含正文的时间摘要写成原生 custom entry。日志写入失败不改变模型回答；不能据缺少记录推断耗时为 0。

## 已验证

- TPA 类型检查通过；扩展另通过 Pi 1.1.0 公开类型的严格检查。
- TPA 针对性测试 50 项通过，含登记、配置、回包、状态、取消和日志。
- 云端针对性测试 26 项通过，含用户隔离、新接口、旧读写回归和账本接口。
- 慢于旧 2 秒期限的假服务返回仍被接受。
- 真实 Pi RPC 取消探针：修正前取消后仍发出一个模型请求；修正后为 0。探针使用本地假模型，付费调用为 0。
- 隔离 HTTP 接口、真实临时 Hindsight 库和原生 Pi 链路完成两组连续回合。模型和推理配置为 Magpie DeepSeek V4.1 Flash、max。

实测发现云端 nullable 来源字段的兼容问题。回归测试先复现，再修正。首组三次模型回答保留，其中两次召回失败。修正后的三次回答另存。

六次实测记录的 `recall_ms` 起点为回合开始，包含召回前的准备时间。最终代码已改为从发起请求计到响应校验完成，并通过假时钟回归。原始实测记录保留，不按新定义改写。
