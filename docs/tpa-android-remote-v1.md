# TPA Android 远程客户端首版

日期：2026-10-15。状态：原生测试 APK、桌面适配器和独立公网中继已实现；真机与真实 Pi 会话尚未验收。

## 已确认的产品方向

只做 Android，验收手机为小米 15 Pro。手机通过用户已有服务器远程连接电脑 TPA，继续同一个会话，接收文字、桌面公开的思考和工具工作流。手机不另起代理，不复制一份记忆，不要求局域网，不传桌面视频。

视觉以用户提供的八张界面为准。最早的自拟概念稿已被替代。当前基准是 `docs/prototypes/tpa-android-v2/`，原生实现位于 `apps/android/src/ui/`。浏览器基准已通过 15 项交互检查并逐页查看；这不代表 Android 真机已经验收。

## 已实现的能力

| 领域 | 当前实现 |
| --- | --- |
| 界面 | 对话首页、工作区弹层、定时任务、任务编辑、项目、项目内对话、新建对话弹层、聊天页；真实系统状态栏、明暗主题 |
| 会话 | 复用 SessionCatalog 与 SessionRuntimeCoordinator；浏览、新建、继续已有 Pi 会话；项目和模型来自电脑 |
| 流式同步 | 从 AgentManager 原有事件订阅正文、思考、工具和运行状态；35 ms 合并变化，按会话游标去重补传，失效回读快照 |
| 停止与确认 | 绑定 sessionId、agentId、runtimeGeneration；拒绝旧运行时操作；被动观察不会重启电脑已停止的进程 |
| 可靠性 | 主机持久化回执先于派发；手机先保存操作身份；丢失回执后查原指令，不自动重新执行；未确认收取的回执不因超过一天而删除 |
| 历史 | 使用桌面稳定 entryId 分页；历史窗口与实时窗口分开，避免把中间缺失的内容拼成连续历史 |
| 定时任务 | 复用桌面 AutomationStore；支持每天和手动，使用电脑的调度时区；没有第二套任务账本 |
| 成果 | 已归档文稿版本按不透明标识列出，分块传输并核对摘要；不接受手机传来的电脑路径 |
| 设备安全 | 电脑确认配对、十分钟邀请、设备撤销、系统保护的本机凭据、加密手机缓存、密文中继 |

## 代码位置

- `apps/android/`：独立 Expo / React Native 工程和依赖，未改变桌面根依赖。
- `packages/tpa-remote/`：协议、解析、增量投影、加密与中继；依赖版本固定。
- `src/main/remote/`：桌面会话、目录、历史、成果、回执、连接的领域适配。
- `src/main/config/RemoteCompanionConfig.ts`：系统加密配置和首次配置收取；只收固定本机位置的禁用配置，不覆盖已有配置。
- `src/main/ipc/remoteCompanionIpc.ts`：状态、配对、撤销三个入口，不透传任意 IPC。
- 桌面设置的“外部连接”页包含 Android 配对入口，并保留原飞书设置。

## 构建与部署

Android 个人签名测试包位于 `E:/A PI/output/TPA/android-companion-0.1.0/TPA-Android-0.1.0-arm64.apk`，约 35 MiB。签名、架构、权限、打包脚本和包内许可说明已核对。密钥、密码和配对材料未放入交付包。

配套 Windows 测试包位于 `E:/A PI/output/TPA/desktop-companion-test/win-unpacked/`。它不是正式发布版本，不会覆盖现有安装。首次配置保持关闭，只有用户在设置生成邀请并确认手机后，才允许远程读取和执行。

中继部署、隔离与回退见 [服务器接入记录](tpa-android-server-readiness-v1.md)。真实公网测试验证 HTTPS、凭据拒绝和加密消息往返；没有调用模型或向真实 TPA 会话发送指令。

## 验证边界

核心远程测试 47 项通过；现有历史读取回归另有 31 项通过，覆盖解析、加密、回执、重连、撤销竞态、历史分页、目录复用和本机配置导入。设置导航及繁体生成物另有 12 项针对性检查通过。桌面与 Android 类型检查通过；桌面三层构建和 Android assembleRelease 通过。

这里的领域测试使用隔离目录及本地真实 WebSocket，Pi 会话边界使用替身。公网验证用合成加密内容。测试数量不能算作真实模型或小米真机验收。

## 尚未达成的部分

1. 小米 15 Pro 未接入，安装、键盘、系统字号、触摸、网络切换及持续流式输出性能待测，不能承诺已达 60 fps。
2. 尚未验证真实电脑 Pi 会话与手机的双向同步，真实模型调用为 0 次。
3. 时间线保留实时尾部窗口，每条最多最后 12,000 字符；超长内容有明确的完整正文、思考或工具输出入口，每段最多 10,000 字符，按内容摘要固定版本读取，单条上限 6,400 万字符。原生分页界面仍需真机验收。Pi 自身没有输出的内容不会补造。
4. 原生正文暂未实现完整 Markdown、代码高亮和附件上传。
5. 首版只接 Pi；DSH、生图、GitHub 工作树、多工作区服务和邀请成员未接入。参考中的相应位置说明边界，不假造可用状态。
6. 文件限 10 MB；电脑离线只能看缓存和保留草稿，没有云端独立代理、自动离线执行或后台推送保证。

下一轮真机检查应先比较八个参考状态，再用一条短消息检查真实流式、停止、确认和网络恢复。真实调用前记录提供商与计费方式，不批量试模型。
